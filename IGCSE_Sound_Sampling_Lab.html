How high can you hear?

Humans hear roughly 20 Hz to 20,000 Hz, and younger people hear higher. This slider changes the pitch of the sound, which is a different thing from the sample rate.

Going further: why 44,100 Hz?

To record a sound accurately you need at least two samples for every wave cycle. The highest sound we hear is about 20,000 Hz, so we need more than 40,000 samples a second. CDs use 44,100 Hz. Try the tune at 4,000 Hz: the higher notes sound wrong because there are too few samples per cycle.

Station 6

Calculate the file size

Work down this station in order. First learn the pieces, then follow a worked example, then try the explorer. The practice questions start with lots of help and slowly take it away.

AThe idea

A sound file is a long list of samples, and every sample uses the same number of bits. So the file size depends on three things:

Sample rateHow many samples are taken each second, in hertz. 44,100 Hz means 44,100 samples every second.
ResolutionHow many bits are used to store each sample. 16 bits means every sample is a 16-digit binary number.
DurationHow long the recording lasts, always in seconds when you calculate.
file size (bits) = sample rate × resolution × duration

Why it works: rate × duration gives the total number of samples. Total samples × bits in each sample gives the total number of bits.

BUnits: fix these before and after

Before you multiply, the sample rate must be in Hz and the time in seconds:
1 kHz = 1,000 Hz
44.1 kHz → 44,100 Hz
1 minute = 60 seconds
3 minutes → 180 s
After you multiply, the answer is in bits. Climb the ladder to the unit the question asks for:
bits
÷ 8→
bytes
÷ 1024→
KiB
÷ 1024→
MiB
÷ 1024→
GiB

Moving to a bigger unit makes the number smaller, so you divide. Moving back down the ladder, you multiply. This course uses 1024, not 1000.

CWorked example

A song lasts 3 minutes. It is recorded at 44.1 kHz with a resolution of 16 bits. Calculate the file size in MiB.

Step 144.1 kHz = 44,100 Hz and 3 minutes = 180 sUnits first: Hz and seconds.
Step 244,100 × 16 × 180 = 127,008,000 bitsSample rate × resolution × duration.
Step 3127,008,000 ÷ 8 = 15,876,000 bytes8 bits in 1 byte.
Step 415,876,000 ÷ 1024 = 15,503.91 KiB1024 bytes in 1 KiB.
Step 515,503.91 ÷ 1024 = 15.14 MiB1024 KiB in 1 MiB. This is the answer, to 2 decimal places.

DExplorer: change the numbers

Try this: double the duration, then double the resolution. What happens to the file size each time?

EMistakes to avoid

  • Forgetting to divide by 8. Your first answer is in bits, not bytes.
  • Dividing by 1000 instead of 1024 when changing to KiB or MiB.
  • Forgetting that kHz must become Hz (× 1,000) and minutes must become seconds (× 60).
  • Stopping one step early. MiB takes two divisions by 1024 after bytes.
  • Rounding in the middle. Keep the full number until the last step.
